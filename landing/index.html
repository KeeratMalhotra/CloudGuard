What it checks

                    
Four checks. The usual suspects.

                    
Each scanner talks to one Google Cloud API, looks for one class of mistake,
                        and explains how to fix it.

                


                

                    

                        

                            

                                
                            

                            CRITICAL
                        

                        
Public bucket exposure

                        
Reads every bucket's IAM policy and flags any binding granted to allUsers or
                            allAuthenticatedUsers, the only two public identifiers in GCP.

                        

                            bucket_scanner.pystorage.Client · get_iam_policy()

                    


                    

                        

                            

                                
                            

                            HIGHMEDIUM
                        

                        
Over-privileged identities

                        
Flags project-wide Owner / Editor bindings, and Google's
                            auto-created default service accounts that quietly ship with Editor.

                        
iam_scanner.pyProjectsClient · get_iam_policy()
                        

                    


                    

                        

                            

                                
                            

                            MEDIUMLOW
                        

                        
Audit trail gaps

                        
Checks whether logs are exported anywhere through a custom sink, and whether the default log
                            bucket keeps them longer than the 30-day minimum.

                        

                            logging_scanner.pyConfigServiceV2Client · list_sinks()

                    


                    

                        

                            

                                
                            

                            CRITICALHIGH
                        

                        
Internet-exposed ports

                        
Finds ingress rules open to 0.0.0.0/0 on SSH, RDP and database ports. It's
                            protocol-aware, so ICMP and disabled rules don't raise false alarms.

                        
firewall_scanner.pyFirewallsClient · list()
                        

                    

                

            

        


        
        

            

                

                    
How it works

                    
Small modules. One shared contract.

                    
Every scanner returns findings in the same shape, so the scorecard can
                        merge, rank and score them without caring where they came from.

                


                

                    

                        
scanbucket_scanner.py

                        
scaniam_scanner.py

                        
scanlogging_scanner.py

                        
scanfirewall_scanner.py

                    

                    
                    

                        

                            merge · score · rank
                            scorecard.py
                            100 − Σ severity weights
                        

                    

                    
                    

                        
outputTerminal report

                        
outputStreamlit dashboard

                    

                


                

                    

                        
The finding contract

                        
Each scan_*() function returns a list of plain dictionaries. Keeping the keys
                            identical across scanners is what lets scorecard.py combine all of them with a
                            simple +=.

                        
    
                            
  • One GCP client per scanner, authenticated through Application Default Credentials
    • 
                            
  • Detection logic returns data instead of printing it
    • 
                            
  • Severity drives both the ordering and the score
    • 
                        

                    

                    

                        
finding.py

                        
{
  "scanner":     "Firewall",
  "severity":    "HIGH",
  "resource":    "default-allow-ssh",
  "description": "TCP port 22 (SSH) open to the entire internet",
  "fix":         "Restrict the source range to trusted IPs"
}

                    

                

            

        


        
        

            

                

                    
Scoring model

                    
Start at 100. Lose points for every gap.

Worked example: a freshly created GCP project

                        

                            100 − (1×20 + 4×10
                            + 3×5 + 1×2) = 23
                        

                        
One public test bucket, the default network's open SSH/RDP rules, a default
                            service account with Editor, two Owners, and default log settings. These are mostly things
                            GCP gives you out of the box.

Running in about ten minutes.

                    
Type your project ID once and every command below updates. Pick your shell,
                        then copy and paste your way down.

  4. 
                        
    04
    
                        
    
                            
    Create a read-only scanner identity
    
                            
    CloudGuard runs as its own service account, not as you. Basic Viewer doesn't
                                include permission to read bucket IAM policies, so two small custom roles fill exactly
                                that gap.
    

                            
    
                                
    PowerShell
    
                                
    gcloud iam service-accounts create cloudguard-scanner --display-name="CloudGuard Scanner"

gcloud iam roles create cloudguardStorageReader --project=YOUR_PROJECT_ID --title="CloudGuard Storage Reader" --permissions="storage.buckets.list,storage.buckets.get,storage.buckets.getIamPolicy" --stage=GA

gcloud iam roles create cloudguardComputeReader --project=YOUR_PROJECT_ID --title="CloudGuard Compute Reader" --permissions="compute.firewalls.list,compute.firewalls.get,compute.networks.list" --stage=GA

gcloud projects add-iam-policy-binding YOUR_PROJECT_ID --member="serviceAccount:cloudguard-scanner@YOUR_PROJECT_ID.iam.gserviceaccount.com" --role="roles/viewer"

gcloud projects add-iam-policy-binding YOUR_PROJECT_ID --member="serviceAccount:cloudguard-scanner@YOUR_PROJECT_ID.iam.gserviceaccount.com" --role="projects/YOUR_PROJECT_ID/roles/cloudguardStorageReader"

gcloud projects add-iam-policy-binding YOUR_PROJECT_ID --member="serviceAccount:cloudguard-scanner@YOUR_PROJECT_ID.iam.gserviceaccount.com" --role="projects/YOUR_PROJECT_ID/roles/cloudguardComputeReader"
    
                            
    

                            
    
                                
    bash / zsh
    
                                
    PROJECT=YOUR_PROJECT_ID
SA="cloudguard-scanner@${PROJECT}.iam.gserviceaccount.com"

gcloud iam service-accounts create cloudguard-scanner --display-name="CloudGuard Scanner"

gcloud iam roles create cloudguardStorageReader --project="$PROJECT" \
  --title="CloudGuard Storage Reader" \
  --permissions="storage.buckets.list,storage.buckets.get,storage.buckets.getIamPolicy" \
  --stage=GA

gcloud iam roles create cloudguardComputeReader --project="$PROJECT" \
  --title="CloudGuard Compute Reader" \
  --permissions="compute.firewalls.list,compute.firewalls.get,compute.networks.list" \
  --stage=GA

for ROLE in roles/viewer \
            "projects/$PROJECT/roles/cloudguardStorageReader" \
            "projects/$PROJECT/roles/cloudguardComputeReader"; do
  gcloud projects add-iam-policy-binding "$PROJECT" \
    --member="serviceAccount:$SA" --role="$ROLE"
done
    
                            
    
                            
    Keep the quotes around --permissions.
                                Without them PowerShell splits the comma list and gcloud rejects it as an invalid
                                permission.

  5. 
                        
    05
    
                        
    
                            
    Generate a key & create your .env
    
                            
    The key file is the scanner's password. It goes in credentials/, which
                                .gitignore already keeps out of git.
    
                            
    
                                
    terminal
    
                                
    mkdir credentials
gcloud iam service-accounts keys create credentials/cloudguard-key.json --iam-account=cloudguard-scanner@YOUR_PROJECT_ID.iam.gserviceaccount.com
    
                            
    

                            
    Then create a file called .env in the project root:
    
                            
    
                                
    .env
    
                                
    PROJ_ID=YOUR_PROJECT_ID
GOOGLE_APPLICATION_CREDENTIALS=C:\path\to\CloudGuard\credentials\cloudguard-key.json
    
                            
    
                            
    
                                
    .env
    
                                
    PROJ_ID=YOUR_PROJECT_ID
GOOGLE_APPLICATION_CREDENTIALS=/path/to/CloudGuard/credentials/cloudguard-key.json
    
                            
    
                            
    You never pass the key to the code yourself. Google's client libraries read
                                GOOGLE_APPLICATION_CREDENTIALS automatically when a client is created
                                (Application Default Credentials).

When something breaks

                    

                        403 … does not have storage.buckets.getIamPolicy access
                        
The service account only has roles/viewer. Basic Viewer can't read IAM policies
                            on buckets, so bind the cloudguardStorageReader custom role from step 04.

                    

                    

                        API has not been used in project <some-other-project>
                        
Your credentials didn't load, so Google fell back to an older login on your machine. Check
                            that GOOGLE_APPLICATION_CREDENTIALS is in .env and points to the
                            real key file.

                    

                    

                        Scanning project 'None' / Required parameter: project
                        
                        
PROJ_ID is missing from .env, or you're running the script from a
                            different folder than the one containing .env.

                    

                    

                        The billing account for the owning project is disabled
                        
Some APIs won't activate without a billing account linked to the project, even if you spend
                            nothing. Link one under Billing, then Link a billing account.

                    

                

            

        


        
        

            

                

                    
Security by design

                    
A security tool should practise what it preaches.

                


                

                    

                        01
                        
Read-only identity

                        
The scanner's service account can list and read configuration. It has no permission to
                            create, change or delete anything.

                    

                    

                        02
                        
Least privilege, by hand

                        
Instead of broad admin roles, two custom roles grant exactly six extra permissions, the
                            minimum the scanners need.

                    

                    

                        03
                        
Secrets stay local

                        
credentials/, *.json and .env are git-ignored from the
                            very first commit, so keys never reach GitHub.

                    

                    

                        04
                        
Metadata, not data

                        
CloudGuard reads policies, rules and settings. It never opens objects inside your buckets,
                            and it runs entirely on your machine.
